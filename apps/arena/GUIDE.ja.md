# Dsh Arena（日本語ガイド）

[English / 中文](README.md)

DeepSeek公式APIとEngyで、同じDsh PTC・同じ指示を同時に実行するローカル比較環境です。左右の会話画面はDsh標準Web UIです。会話・推論・ツールカード・履歴の描画を作り直さず、上部に比較用の計測欄と開始操作を追加します。

## 起動

Docker Desktopを起動し、`uv`をインストールします。Dockerには5 vCPU以上・約4 GiB以上を割り当てます。

```sh
./apps/arena/setup.sh
./apps/arena/run.sh --open
```

このチェックアウトではセットアップ済みです。画面は `http://127.0.0.1:8765`、Docker用ゲートウェイは8766番です。別のポートは `./apps/arena/run.sh --port 8865` のように指定します。

「接続設定」でAPIキーを入力し、「同時スタート」を押します。既存の `DEEPSEEK_API_KEY` / `ENGY_API_KEY`、Git管理外のルート `.env`、または `.arena/keys.env` からも読み込みます。キーの保存は任意で、保存時は0600のファイルを使います。ブラウザへキーを返さず、エージェントへはそのレーン専用のゲートウェイ資格情報だけを渡します。

有料APIを呼ばずに、実際のDsh・PTC・Docker・採点・修正・再採点を確認できます。

```sh
./apps/arena/run.sh --port 8775 --demo
```

デモは意図的にTTLのバグがある実装を生成し、採点結果を受け取って修正します。デモ画面のトークン数・料金・速度は模擬値として明示します。

## 同時開始と公平性

両レーンのDshを初期化し終えてから同じタスクを投入します。最初の推論リクエストはゲートウェイで待ち合わせ、モデルID以外のJSONフィールドが完全に一致した場合だけ両方を解放します。実際の送信時刻の差を表示します。HTTPの送信を同じイベントループから開始する保証であり、提供元への到着時刻までの一致は保証しません。

両側は同じDockerイメージID、読み取り専用の同じPTC設定、`high`、同じ出力上限、同じ `/workspace` を使います。Dsh標準UIとSDKは各レーンの同じプロセスを参照します。初回リクエストに乱数・時刻を含めないため、提供元向けのSession-log付加情報と補助的なタイトル生成は無効にします。

各エージェントは2 vCPU、1536 MiB、128プロセス、256 MiBの作業用tmpfsです。左右を重複しない同数のDocker VMのCPUに固定し、スワップを無効にします。作成後のDocker設定を検査して、実際の上限も記録します。推論サーバーのGPU・混雑・量子化・キャッシュ状態は提供元が管理しており、この環境で同一化できません。

採点器は各側とも0.5 vCPU・256 MiB上限、ネットワークなしです。対象のエージェントを一時停止して安定したスナップショットを取得し、別コンテナで採点します。採点器はrootの保護されたディレクトリに置き、提出サーバーを別のUIDで実行します。エージェント側のイメージに採点器・参照実装・テストを含めません。

各レーンのネットワークも別々に隔離します。エージェントが接続できる外向きの経路は、モデル用ゲートウェイの固定ポートへバイト列を中継する専用プロセスだけです。ホストの操作APIや他方のレーンへ直接接続できません。中継も両側同じイメージ、0.25 vCPU・64 MiB上限、IP転送なしで起動し、Dockerが適用した設定を記録します。実コンテナから、モデル通信の成功と、IPアドレスを直接指定した操作APIへの接続拒否を検査します。

## 自動採点

無出力の時間ではなく、Dsh SDKのターン終了で採点します。ツール実行中やAPI待機中の沈黙では起動しません。通信失敗・中断には提出物の点数を割り当てません。

23の検査には、TCP分割・パイプライン・任意のバイト列・整数境界・TTL・再起動・8クライアントの同時更新と、固定seedによる1600操作の照合が含まれます。独立した検査は4件並列、生成した連続操作はプロセスを再利用します。CPU時間とcgroupのピークメモリも結果に記録します。

JSONレポートを保存し、同じJSONを同じDshセッションへ返します。失敗時は修正を続け、合格時は結果の確認を求めます。その確認後も採点済みファイルが変わっていない場合に完了します。既定は修正6ラウンド・各推論32768 token・累計出力500000 token・全体1時間です。上限に達した最終レポートもセッションへ投入しますが、追加の推論は許可しません。

終了後も標準Dsh画面で結果を読めます。「停止」、次の開始、またはコントローラー終了で残ったレーンを回収します。JSONLの実行ログ、固定条件、採点レポート、提出物tar、集計は `.arena/runs/<run-id>/` に保存します。

## 計測

| 項目 | 定義 |
| --- | --- |
| Token/s | 直近の完了リクエストの `(API報告output tokens - 1) / 最初〜最後の内容deltaの秒数`。チャンク数をtoken数に置き換えません。 |
| Ping | 認証付きモデル一覧GETのHTTP往復時間。ICMPではありません。 |
| TTFT | 推論リクエスト送信から最初の内容deltaまで。推論・本文・ツール引数を含みます。 |
| Input | Anthropic形式の非キャッシュ入力、cache read、cache creationの合計。 |
| Cached input / % | API報告のcache read token数、および総入力に占める割合。 |
| Pricing | 設定したUSD/100万tokenに基づく概算。未完了・usage欠落のリクエストを区別します。 |

DeepSeek公式の初期レートはピーク料金です。[公式のオフピーク料金](https://api-docs.deepseek.com/quick_start/pricing/)を使う場合は設定で各レートを半額にします。Engyも[料金表](https://engy.ai/pricing)に合わせて変更できます。請求実額の取得や上流の未報告tokenの推定は行いません。各リクエストに適用したレートをログに残します。

## 形式証明と検証範囲

`formal/Arena.lean` はLean 4.35.0で18の定理を検査します。同時開始には両側の準備が必要であること、採点・フィードバック・合格への遷移条件、終了状態の吸収性、同数で互いに重ならないCPU番号の割当、参照モデルのTTL・整数上限・キャッシュ入力の課金分割などが対象です。Leanから列挙した遷移表とPythonが使う表の一致も検査します。`sorry`や独自の公理は許可しません。

これは上記の仕様モデルに対する証明です。Python実装全体、TCP/OS/Dockerの実装、任意の提出プログラムの正しさ、上流モデルの同一性、すべての入力を網羅する完全な採点器を形式証明したものではありません。有限のテストが任意のプログラムの完全な正しさを保証するという主張はしません。

実装との対応は、境界・プロパティテスト、本物のRedisとの1600操作の照合、正しい対照実装、6種類の欠陥実装の拒否で確認します。検証したソースのSHA-256を `.arena/verification.json` に保存し、対象ファイルが変更された場合は再検証とコントローラーの再起動まで本実行を開始しません。

```sh
./apps/arena/verify.sh
uv run --directory apps/arena pytest -q
```

Leanは公式リリースの固定SHA-256を確認してチェックアウト内のキャッシュに展開します。レーンは公開元の最新版へ自動追従せず、forkのソースと `pnpm-lock.yaml` からビルドします。
